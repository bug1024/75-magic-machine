# 75's MAGIC MACHINE

一个给女儿做的网页小玩具。

按下空格，魔法机器就会亮起来：彩灯追逐、小球翻腾、扭蛋落下，最后冒出一件宝物。宝物里有她熟悉的小海豚、吱吱猫头鹰、丫丫三花猫，也有公主裙、月亮城堡和一些让人笑出声的小东西。

想做的是一个她能自己玩、每次打开都有一点期待的小世界。虚拟的裙子、会飞的宝石或可爱的便便，都可以成为让她开心的惊喜。

## 设计理念

### 操作简单，过程热闹

主要操作只有一个：按空格键，或点击「开启魔法」。空格键始终用于启动抽奖，焦点停在哪个按钮上都不会改变它的用途。

乐趣也在等待宝物出现的过程中。能量注入、小球碰撞、落球、摇晃、开壳，每个阶段都有动作和声音反馈，让一次简单的点击变成一场小小的魔法表演。彩色灯光、夸张动画和带节奏的中奖音乐共同营造气氛；声音和柔和动画可以单独切换。

机器有 10 格魔法能量，每次抽奖消耗一格。剩余不超过 3 格时，屏幕边缘以红色脉冲闪烁，并间歇播放专属提示音；能量耗尽后，可以用数学题给机器充电。答对一题增加一格，最多存满 10 格，答错不扣能量，也没有倒计时。机器底部用爱心显示剩余能量；进入答题面板后暂停预警，静音关闭提示音，柔和动画保留静态红色提醒。补充能量的过程同样是一场有小星星和声音反馈的魔法。

### 熟悉的生活，也能成为魔法

宝物把现实中的玩具、家人、宠物和想象中的物品放在一起。每件都有自己的插画、名字、描述和开奖效果，让孩子熟悉的小东西也能带来新鲜感。所有宝物都是虚拟奖励，收藏记录留在当前浏览器中。

### 宝物由配置驱动

宝物内容与抽奖流程分开。`treasures.json` 定义「有什么宝物、出现的概率、长什么样、用什么效果」，程序负责抽取和演出。

添加宝物时，可以直接补充配置和 SVG 插画，复用已有的星光、彩虹、月光或泡泡效果。如果需要新的表现，再扩展对应的动画或音效实现。

### 让魔法世界慢慢长大

正常开奖结束后，魔法伙伴偶尔会来拜访：仙子补充爱心，捣蛋幽灵吸走一格能量，快递精灵送来额外宝物。事件有独立的角色、动作和声音，奖励写入收藏；能量不足时，幽灵不会吸能量。

每完成 50 次正常抽奖，邪恶女巫就会来捣蛋。她直接在主页面星空中的四个固定位置闪现，每次停留约 2.8 秒；点击女巫后，主抽奖机会发射收藏中的宝物；命中 3 次就能赶跑她，获得一件额外宝物。没有倒计时，打空可以继续尝试，发射不会扣能量或减少收藏。手机可以直接点按女巫，键盘可用 Tab 聚焦后按 Enter；空格仍只负责抽奖，在挑战中不会触发其他操作。

机器也会随着游玩成长。累计完成 10 次正常抽奖后解锁彩虹机器，拥有彩虹外壳、拱门和新的启动旋律；20 次解锁飞翼机器，两侧展开星光翅膀，脚下托起云朵，启动时扇翅腾空；35 次解锁城堡机器，保留翅膀与云朵，长出皇冠和塔楼，开奖时打开魔法城堡门。每次升级都有独立的庆祝演出。升级不消耗能量或收藏，赠送的宝物不推进升级次数。

### 保持轻巧，方便打开

使用原生 HTML、CSS 和 JavaScript，没有框架、CDN 或后端。构建后，配置、插画、样式和脚本全部内嵌到一个 `index.html`，可以复制到其他电脑，直接用浏览器打开。

## 试玩

用 Chrome / Edge 打开 `index.html` 即可游玩。

- 按空格键或点击「开启魔法」抽取宝物。
- 右上角可以切换声音、柔和动画和全屏。
- 「我的宝藏」展示收集到的宝物。
- 「充能」随时可打开数学小站，简单、中等、困难分别对应 10、20、100 以内的加减法，运算数和结果均在范围内，减法不出现负数。简单题配有可数的星星；答错后可以看提示再试。
- 能量耗尽时，启动按钮和空格键会引导进入充能小站；答题面板内空格不操作其他功能，可以使用数字键盘或键盘输入。正确答案会自动提交并播放祝贺音效；错误答案点击「送出答案」或按 Enter 后，会播放重试音效。充满能量会触发爱心、光环与彩色星星的庆祝动画。
- 「作弊模式」默认关闭；开启后，所有参与抽取的宝物等概率出现。
- 完成 10、20、35 次正常抽奖，分别解锁彩虹、飞翼、城堡机器；形态会一直保留。
- 每完成 50 次正常抽奖，女巫会在主屏幕星空中闪现。点击或点按她，宝物从抽奖机飞出，命中 3 次后获得额外奖励。挑战期间暂停抽奖和充能，声音与柔和动画仍可切换；能量为零也能完成挑战。

目前共有 33 件宝物。普通模式按配置权重独立抽取；作弊模式下，每件概率约为 3.03%。两种模式都允许重复抽中同一件宝物。

部分宝物可以在开奖后点击互动：恐龙打嗝喷泡泡、云朵下糖果雨、果冻兔弹跳、飞龙绕圈、蘑菇轮流唱出三个乐句、星星种子开花、飞船起飞、袜子跳舞。互动不消耗能量，也不会重复发奖；聚焦宝物后按 Enter 同样可以互动，空格仍然只用于启动抽奖。柔和动画模式保留插画变化、静态装饰和音效。

能量、题目难度、收藏、机器成长、待处理事件、女巫命中进度和声音、动画偏好使用 `localStorage` 保存，存档键为 `75-magic-machine:v1`。存档属于当前浏览器和访问地址，不上传服务器，也不会在设备之间同步。作弊模式每次打开或刷新页面都会重置为关闭；浏览器无法保存收藏时，页面会给出提示。

## 项目结构

```text
75-magic-machine/
├── game-config.json     # 能量、数学题、随机事件、升级与女巫挑战规则
├── treasures.json       # 宝物配置
├── assets/              # 独立 SVG 插画
├── src/
│   ├── template.html    # 页面结构
│   ├── style.css        # 基础布局、宝物效果与响应式样式
│   ├── gacha.css        # 抽奖机灯光与演出动画
│   ├── engine.mjs       # 配置校验、概率抽取与历史记录校验
│   ├── energy.mjs       # 能量规则、存档恢复与数学出题
│   ├── recharge.js      # 充能小站、数字键盘与答题反馈
│   ├── energy.css       # 能量格、低能量预警与充能面板
│   ├── world-engine.mjs # 事件概率、成长门槛、挑战里程碑与存档校验
│   ├── world.js         # 事件队列、奖励结算、升级仪式与女巫挑战调度
│   ├── world.css        # 角色动画和彩虹机器外观
│   ├── evolution.css    # 飞翼、云朵、城堡形态与升级动作
│   ├── witch.js         # 星空闪现、宝物发射、命中与胜利反馈
│   ├── witch.css        # 主屏幕女巫、挑战状态与弹道动画
│   ├── treasure-play.js # 配置驱动的宝物点击互动
│   ├── treasure-play.css # 宝物出场动作与互动反馈
│   ├── chamber.js       # 魔法舱小球运动、碰撞与选球
│   ├── audio.js         # Web Audio 合成音效和中奖音乐
│   └── app.js           # 开奖流程、粒子、交互与本地收藏
├── build.mjs            # 将源文件和资源打包为单个 HTML
├── tests/               # 抽奖逻辑与浏览器验证
└── index.html           # 可直接打开的游戏
```

一次抽奖由 `app.js` 串起各个阶段：

```text
启动 → 注入能量 → 小球翻腾 → 选球落下 → 摇晃开壳 → 宝物揭晓 → 收藏
```

`engine.mjs` 在启动时选定结果，`chamber.js`、CSS 动画、粒子和音效共同完成演出。魔法舱展示的小球数量和碰撞过程不影响概率。宝物揭晓时才写入收藏，抽奖进行中会锁定重复启动和模式切换。

正常宝物揭晓后，`world-engine.mjs` 推进成长次数并生成升级、随机事件或女巫挑战计划，`world.js` 在开奖演出结束后依次执行。计划和结算结果一起保存在本地，赠品统一写入收藏，但不会推进成长次数。

## 配置宝物

编辑 `treasures.json` 中的 `treasures` 数组：

| 字段 | 作用 |
| --- | --- |
| `id` | 唯一、稳定的标识，用于关联收藏 |
| `name` / `description` | 宝物名称和揭晓描述 |
| `rarity` | `common`、`rare`、`super`，决定稀有度展示；`super` 带有额外的开奖预告 |
| `weight` / `enabled` | 抽取权重和启用状态，停用或零权重宝物不参与抽取 |
| `appearance` | SVG 路径、备用图标和主题配色 |
| `effects` | 揭晓动画、持续粒子、中奖音效和效果参数 |

普通模式下，单件宝物的概率为它的权重除以所有参与抽取宝物的总权重。稀有度和权重可以分别配置，作弊模式只临时改变抽取概率。

插画放在 `assets/` 下，通过 `appearance.image` 引用。效果 ID 在 `src/engine.mjs` 注册；动画、粒子和声音分别由 CSS、`src/app.js` 和 `src/audio.js` 实现。配置只保存数据，未知效果会降级到基础效果。

`effects.interaction` 选择点击互动效果；`appearance.interactionImage` 可指定互动后的插画，例如种子开花。新增互动先在 `INTERACTIONS` 注册，再在 `treasure-play.js`、`treasure-play.css` 和 `audio.js` 实现对应表现。所有插画随构建内嵌，离线也能互动。

能量参数集中在 `game-config.json`：`energy` 定义初始值、上限、预警阈值、抽奖消耗和答题奖励；`math` 定义默认难度和各档范围。抽奖启动时扣除并保存能量，刷新不会恢复满格；流程异常且未发放宝物时退回本次消耗。作弊模式只调整宝物概率，仍消耗能量。

## 魔法事件与机器成长

`game-config.json` 的 `world` 定义事件和升级规则：

| 配置 | 作用 |
| --- | --- |
| `enabled` / `chance` | 随机拜访开关与基础触发概率，目前为 15%；女巫挑战有独立开关 |
| `minGap` | 两次事件之间至少有 3 次无事件抽奖；首次游玩的前三次也不触发 |
| `guaranteeAfter` | 连续 8 次无事件时保证出现一次 |
| `rainbowAt` | 解锁彩虹机器所需的正常抽奖次数，目前为 10 次 |
| `wingedAt` / `castleAt` | 解锁飞翼、城堡机器的次数，目前为 20 / 35 次；门槛严格递增 |
| `events` | 角色插画、启用状态、选择权重、能量变化与演出时长 |
| `witch` | 女巫挑战的独立开关、间隔次数、所需命中次数、闪现停留/隐藏时长与插画 |

魔法仙子最多补充 2 格能量；已满格时改送一件宝物。幽灵吸走 1 格，但剩余能量不超过预警阈值时不会被选中，结算时也会再次检查。快递精灵赠送一件按当前抽奖模式选出的宝物。额外礼物与正常宝物一起收藏，标记为事件奖励，不增加正常抽奖次数。

事件与升级仪式停留 10 秒，也可以在效果发生后点击「继续玩」。演出过程中锁定重复抽奖，暂时暂停低能量预警音；静音、柔和动画和后台暂停仍然有效。升级形态保存在当前浏览器中，旧存档会按累计次数恢复对应形态，不重播已经达到的升级。

成长次数不受收藏的 1000 条记录上限影响。事件计划会保存到本地，刷新后继续尚未结算的事件；能量或礼物结算时同时移除计划，防止重复奖励。旧存档按已有的正常收藏记录初始化成长次数。

女巫在第 50、100、150…次正常开奖后出现，同一次开奖不再触发随机拜访；如与升级重合，先升级，再进入挑战。命中次数实时保存，刷新后继续当前挑战。胜利礼物按照触发挑战时的抽奖模式预先选定，结算时与移除挑战一起保存，礼物不推进抽奖次数。旧存档不会补发过去的女巫挑战，只在后续达到新的里程碑时触发。静音和柔和动画有效，切到后台时暂停闪现与发射流程。

女巫直接出现在星空背景中，主抽奖机保持可见。四个闪现位置根据屏幕和机器位置计算，女巫不会连续出现在同一个位置。手机上会暂时拉远机器视图，为两侧的点按区域留出空间；胜利后点击「继续玩」或等待 10 秒，恢复正常抽奖。

`world.witch` 的参数可以单独调整：

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `enabled` | `true` | 是否触发女巫挑战 |
| `every` | `50` | 每多少次正常开奖触发一次 |
| `hits` | `3` | 赶跑女巫所需的命中次数 |
| `visibleMs` | `2800` | 每次闪现的停留时间，单位毫秒 |
| `hiddenMs` | `450` | 两次闪现之间的隐藏时间，单位毫秒 |
| `image` | `assets/witch.svg` | 女巫插画路径，构建时内嵌 |

## 本地开发

构建和逻辑测试需要 Node.js，无需安装第三方依赖。

```sh
npm run build   # 生成 index.html
npm test        # 验证配置、概率抽取、能量与数学题逻辑
npm start       # 启动本地服务，需要 Python 3
```

本地服务地址为 `http://localhost:7575`。修改源文件、宝物配置或插画后，运行 `npm run build` 更新游戏。

`tests/` 中还提供可选的 Playwright 浏览器验证脚本，用于检查完整开奖流程、键盘交互、收藏保存、充能、机器升级、宝物互动、女巫挑战和手机布局。`witch-browser.mjs` 验证真实第 50 次开奖、主屏幕弹道、三次命中、打空与连点保护、刷新续战、奖励只发一次，以及触摸操作和专属音效。运行这些脚本需要环境中已有 Playwright 和 Chrome，可通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径。
